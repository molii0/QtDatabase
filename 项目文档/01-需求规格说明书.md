## 1. 引言

### 1.1 编写目的

本文档定义充电桩应用管理平台的全部功能需求与非功能需求，作为三类读者的共同依据：

- **学生（）**：明确每个模块要做什么、做到什么程度算完成。
- **AI 代码生成工具**：作为长期上下文源，避免每次对话重述需求导致 token 浪费和理解漂移。
- **实训验收方**：逐条对照验收标准检查交付物。

### 1.2 术语与缩写

| 术语           | 说明                             |
| ------------ | ------------------------------ |
| 电站 / Station | 一个物理充电站点，含地址与经纬度，下挂多个电桩        |
| 电桩 / Charger | 一个具体充电设备，属于某个电站，有类型、功率、状态      |
| 订单 / Order   | 一次充电行为的记录，从预约创建到结算完成           |
| 免密登录         | 仅凭手机号登录，手机号不存在时自动注册            |
| 未结算订单        | `status` 为预约(0) 或 充电中(1) 的订单   |
| Haversine    | 球面两点距离公式，用于本地计算用户与电站的直线距离      |
| SoC          | State of Charge，电池荷电状态，本项目用模拟值 |

### 1.3 需求编号规则

```
UC-<子系统>-<序号>      用例（功能需求）
NFR-<类别>-<序号>       非功能需求
BR-<序号>               业务规则
```

子系统代号：`U` 用户端、`A` 管理端、`D` 数据库端、`W` Web 大屏、`M` 机器学习。

## 2. 总体描述

### 2.1 系统定位

平台覆盖 **用户服务 → 设备运维 → 数据存储 → 决策分析 → 智能预测** 全链条，由五个子系统构成：

| 子系统          | 形态               | 技术                     | 优先级  |
| ------------ | ---------------- | ---------------------- | ---- |
| 充电用户端        | 桌面 GUI（模拟手机竖屏）   | Qt Widgets             | P0   |
| PC 服务器端（管理端） | 桌面 GUI（宽屏 PC 风格） | Qt Widgets + Qt Charts | P0   |
| 数据库端         | 单文件数据库           | SQLite 3               | P0   |
| 大数据可视化大屏     | Web 页面           | Vue 3 + ECharts        | P1   |
| 机器学习智能分析     | 离线脚本 + 结果回写      | Python + scikit-learn  | P1   |

### 2.2 用户角色

| 角色    | 描述                    | 入口                |
| ----- | --------------------- | ----------------- |
| 车主用户  | 电动汽车车主，查站、导航、充电、充值    | `ncs_user` 可执行程序  |
| 运营管理员 | 平台运维人员，监控设备、分析营收、管理用户 | `ncs_admin` 可执行程序 |
| 决策者   | 查看大屏看板，不做操作           | 浏览器打开大屏页面         |

### 2.3 运行环境假设

- 单机部署，两个客户端程序访问**同一个** SQLite 数据库文件。
- 无真实 GPS 硬件，用户位置由界面选择区域或输入地址后**软件模拟**。
- 无真实充电桩硬件，充电过程由定时器按功率模拟累积电量。
- 腾讯地图为可选外部依赖：有网络且配置了 Key 时用真实地图，否则退化为本地 Haversine 距离计算 + 系统浏览器打开地图链接。

### 2.4 业务规则（全局约束）

| 编号    | 规则                                       |
| ----- | ---------------------------------------- |
| BR-01 | 手机号是用户唯一标识，必须为 11 位数字且以 1 开头             |
| BR-02 | 一个用户同一时刻最多只能有一个未结算订单                     |
| BR-03 | 一个电桩同一时刻最多只能被一个订单占用                      |
| BR-04 | 开始充电前用户余额必须大于最低起充金额（默认 5 元）              |
| BR-05 | 充电费用 = 累计电量(度) × 该电站单价(元/度)，保留 2 位小数     |
| BR-06 | 结算时从用户余额扣款，余额不足则扣至 0 并记录欠费金额             |
| BR-07 | 被冻结（`status=0`）的用户不能登录，不能开始新的充电          |
| BR-08 | 故障（`status=2`）的电桩不可被预约或开始充电              |
| BR-09 | 所有金额字段单位为元，所有电量字段单位为度(kWh)，所有时间存储为本地时间字符串 |
| BR-10 | 删除电站时若其下仍有电桩，禁止删除并提示                     |

## 3. 充电用户端需求（UC-U）

### UC-U-01 手机号免密登录 / 自动注册

**角色**：车主用户
**前置条件**：程序启动，数据库可连接。

**主流程**

1. 显示登录窗口，含手机号输入框、"获取验证码"按钮（模拟，点击后按钮进入 60 秒倒计时）、验证码输入框、"登录/注册"按钮。
2. 用户输入 11 位手机号，点击"获取验证码"，系统生成 6 位随机码并直接在界面提示区显示（模拟短信下发）。
3. 用户输入验证码，点击登录。
4. 系统校验验证码一致后，按手机号查询 `user` 表。
5. 手机号存在且 `status=1` → 登录成功，加载用户信息进入主窗口。
6. 手机号不存在 → 插入新用户，昵称默认 `用户` + 手机号后 4 位，头像为空（界面显示默认灰色头像），余额 0，状态正常，随后登录成功。

**异常流**

| 编号   | 条件         | 系统响应                      |
| ---- | ---------- | ------------------------- |
| E1   | 手机号格式不合法   | 提示"请输入正确的 11 位手机号"，不查询数据库 |
| E2   | 未获取验证码直接登录 | 提示"请先获取验证码"               |
| E3   | 验证码错误      | 提示"验证码错误"，允许重试            |
| E4   | 用户已被冻结     | 提示"账号已被冻结，请联系客服"，拒绝登录     |
| E5   | 数据库打开失败    | 提示具体错误并允许退出程序             |

**验收标准**

- 新手机号首次登录后，`user` 表新增一条记录，昵称符合默认规则。
- 同一手机号第二次登录不再新增记录，且能带出上次修改过的昵称和余额。
- 管理端把该用户冻结后，用户端再次登录被拒绝。

---

### UC-U-02 附近充电站查询

**前置条件**：用户已登录。

**主流程**

1. 主窗口默认进入电站列表页。
2. 页面顶部提供定位区：区域下拉框（预置若干城市/城区）+ 地址输入框 + "定位"按钮。
3. 用户选择区域或输入地址后点击定位：
   - 若已配置腾讯地图 Key 且网络可用 → 调用地理编码接口把地址转为经纬度。
   - 否则 → 使用区域下拉框对应的预置经纬度作为当前位置。
4. 系统读取全部电站，用 Haversine 公式计算每个电站与当前位置的距离，按距离升序排列。
5. 列表以卡片形式展示每个电站：站名、单价（元/度）、`空闲数/总桩数`、距离（公里，保留 1 位小数）。
6. 卡片上的空闲数量根据 `charger` 表实时统计（`status=0` 计为空闲）。

**异常流**

| 编号   | 条件          | 系统响应                       |
| ---- | ----------- | -------------------------- |
| E1   | 地址解析失败或网络超时 | 提示"地址解析失败，已使用默认位置"，退化为预置坐标 |
| E2   | 电站表为空       | 列表区显示占位文案"暂无充电站数据"         |

**验收标准**

- 切换不同区域后列表顺序随之变化，距离数值合理（同城应在几公里到几十公里量级）。
- 管理端把某个电桩状态改为使用中后，用户端刷新，对应电站空闲数减 1。

---

### UC-U-03 电站详情与电桩列表

**主流程**

1. 用户点击电站卡片，进入电站详情页。
2. 顶部显示电站名称、详细地址、单价、距离。
3. 中部以表格展示该站所有电桩：编号、类型（快充/慢充）、功率(kW)、状态（空闲/使用中/故障）、累计充电次数。
4. 状态列用不同颜色文字区分：空闲绿色、使用中橙色、故障红色。
5. 底部提供"一键导航"和"选桩充电"两个按钮。

**验收标准**：表格行数与该电站 `charger` 记录数一致；状态文字与数据库值对应正确。

---

### UC-U-04 一键导航

**主流程**

1. 用户在电站列表点击距离信息，或在详情页点击"一键导航"。
2. 打开导航页，页面顶部提供出行方式选择：驾车 / 步行 / 公交。
3. 页面主体为地图区域：
   - **方案 A（已装 Qt WebEngine 且配置了 Key）**：`QWebEngineView` 加载本地 HTML 模板，模板内用腾讯地图 JS API 渲染地图并绘制起点到终点的路线。
   - **方案 B（兜底）**：显示起终点坐标与直线距离信息卡，提供"在系统浏览器中打开"按钮，用 `QDesktopServices::openUrl` 打开腾讯地图路线规划 URL。
4. 起点为当前定位位置，终点为目标电站经纬度。

**异常流**：网络不可用时页面显示明确提示，不崩溃、不空白假死。

**验收标准**：能截图到地图路线规划画面（方案 A 内嵌截图，方案 B 浏览器截图）。

---

### UC-U-05 用户中心与信息维护

**主流程**

1. 底部导航点击"我的"进入用户中心。
2. 展示：头像（圆形，未设置时显示默认灰色头像）、昵称、手机号（中间 4 位打码）、钱包余额、注册时间。
3. **更换头像**：点击头像 → 文件选择对话框（限 `*.png *.jpg *.jpeg *.bmp`）→ 图片复制到应用数据目录 `avatars/` 下并以用户 ID 命名 → 数据库保存相对路径 → 界面立即刷新。
4. **修改昵称**：点击编辑 → 输入框可编辑 → 保存后写库并刷新。昵称长度 1-20 字符，不允许纯空白。
5. **余额充值**：输入金额（0.01 - 10000，两位小数）→ 点击充值 → 弹出"支付成功"模拟提示 → 余额累加并写库 → 生成一条充值流水（可选，记入 `recharge_log`）。
6. **退出登录**：返回登录窗口，清空当前会话。

**异常流**

| 编号   | 条件                 | 系统响应                   |
| ---- | ------------------ | ---------------------- |
| E1   | 选择的图片文件过大（> 5MB）   | 提示"图片过大，请选择 5MB 以内的图片" |
| E2   | 充值金额非法（非数字、≤0、超上限） | 输入框标红并提示合法范围，不写库       |
| E3   | 昵称为空或全空格           | 提示"昵称不能为空"，保留原值        |

**验收标准**：修改昵称、头像、余额后重启程序仍然保留；充值 100 元后余额精确增加 100.00。

---

### UC-U-06 充电前未结算订单拦截

**前置条件**：用户已登录，点击"充电"入口。

**主流程**

1. 进入充电页面前，系统查询当前用户是否存在 `status IN (0,1)` 的订单。
2. **存在** → 模态弹窗提示"您有未完成的充电订单，请先结算"，仅提供"去结算"按钮，点击后强制跳转订单结算页，不允许进入选桩流程。
3. **不存在** → 正常进入选桩页面。

**验收标准**：制造一条充电中订单后，反复点击充电入口都会被拦截到结算页。

---

### UC-U-07 选桩、预约与开始充电

**主流程**

1. 选桩页展示当前电站的空闲电桩（仅 `status=0`），显示编号、类型、功率。
2. 用户选中一个电桩，点击"预约"：
   - 校验用户余额 ≥ 起充金额（BR-04）。
   - 事务内：电桩状态置为使用中(1)，插入订单记录（`status=0` 预约，`start_time` 为空）。
3. 预约成功进入充电控制页，显示电桩信息与"开始充电"按钮，并显示预约保留倒计时（默认 15 分钟，超时自动取消预约并释放电桩）。
4. 用户点击"开始充电"：订单 `status` 置为 1（充电中），`start_time` 写入当前时间，启动计费定时器。

**异常流**

| 编号   | 条件           | 系统响应                           |
| ---- | ------------ | ------------------------------ |
| E1   | 余额不足         | 提示"余额不足，请先充值"，提供跳转充值入口         |
| E2   | 电桩已被他人占用（并发） | 事务失败回滚，提示"该电桩刚被占用，请重新选择"并刷新列表  |
| E3   | 预约超时未开始      | 自动取消订单（`status=3` 已取消），电桩释放为空闲 |

---

### UC-U-08 实时计费

**主流程**

1. 充电中页面每秒刷新，显示：充电时长（HH:MM:SS）、累计电量（度）、当前费用（元）、实时功率（kW）、模拟 SoC 进度条。
2. 电量按 `功率(kW) × 已充时长(小时)` 累积，费用按 BR-05 计算。
3. 为便于演示，引入**时间加速倍率**（配置项 `charge.time_scale`，默认 60，即 1 秒模拟 1 分钟），使一次充电在 1-2 分钟内可演示完整流程。
4. 页面提供"结束充电"按钮。
5. 程序意外退出后重新登录，能从 `start_time` 恢复计费，继续显示正确的时长与费用。

**验收标准**：连续观察 30 秒，电量与费用单调递增且与功率、单价换算一致；杀掉进程重启后数据不丢。

---

### UC-U-09 结束充电与订单结算

**主流程**

1. 用户点击"结束充电"，二次确认。
2. 事务内完成：
   - 订单 `end_time` 写入当前时间，`energy`、`amount` 写入最终值，`status` 置为 2（已完成）。
   - 电桩 `status` 置回 0（空闲），`total_count` 加 1，`total_minutes` 累加本次时长。
   - 用户余额扣减 `amount`（按 BR-06 处理余额不足）。
3. 跳转结算页，展示订单小票：订单号、电站名、电桩编号、开始/结束时间、充电时长、电量、单价、总金额、扣款后余额。
4. 提供"完成"按钮返回首页。

**异常流**：任一步失败则整体回滚，提示"结算失败，请重试"，订单保持充电中状态。

**验收标准**：结算后电桩恢复空闲、用户余额减少的金额与小票一致、管理端营收统计相应增加。

---

### UC-U-10 我的订单

**主流程**：列表展示当前用户历史订单，倒序排列，显示电站名、电桩编号、时间、电量、金额、状态；点击查看小票详情。

## 4. PC 服务器端（管理端）需求（UC-A）

### UC-A-01 管理员登录

**主流程**

1. 登录窗口输入账号、密码，点击登录。
2. 系统查询 `admin` 表校验，默认初始账号 `admin / 123456`。
3. 成功进入管理后台主界面，标题栏显示当前管理员账号。

**异常流**：账号或密码错误统一提示"账号或密码错误"（不区分，避免撞库探测）；连续失败 5 次锁定输入 30 秒。

**验收标准**：`admin/123456` 可登录；错误密码被拒绝。

---

### UC-A-02 管理后台主界面

**主流程**

1. `QMainWindow` 布局：左侧导航栏（营收分析 / 电桩状态 / 充电桩管理 / 充电站管理 / 用户管理 / 智能预测），右侧 `QStackedWidget` 承载页面。
2. 顶部工具栏提供"刷新"和"退出登录"。
3. 底部状态栏显示数据库路径、当前时间、在线电桩数概览。

---

### UC-A-03 销售业绩分析

**主流程**

1. 顶部三个指标卡：今日营收、本月营收、总营收（金额保留 2 位小数）。
2. 中部折线图（`QChart` + `QLineSeries`）展示营收趋势，提供"近 7 日 / 近 30 日"切换按钮。
3. 下方柱状图（`QBarSeries`）展示同期每日订单量。
4. 数据来源为对 `charging_order` 表按日期分组的 SQL 聚合（仅统计 `status=2` 的订单）。

**异常流**：区间内无数据时图表显示空坐标轴与"暂无数据"文案，不报错。

**验收标准**：能截图到折线图与柱状图；用户端完成一笔订单后点刷新，今日营收增加对应金额。

---

### UC-A-04 电桩状态总览

**主流程**

1. 表格展示三种状态（在用 / 闲置 / 故障）的数量与占比百分比。
2. 配合一个饼图直观展示占比。
3. 底部显示设备健康度评分（简单规则：`(空闲+使用中)/总数 × 100%`）。

---

### UC-A-05 充电桩管理

**主流程**

1. `QTableView` 列表展示：电桩编号、所属电站、类型、功率(kW)、当前状态、累计充电次数、累计充电时长（小时）。
2. 支持按电站筛选、按状态筛选、按编号搜索。
3. 选中某电桩后可执行操作：
   - **远程重启**：模拟下发重启指令，弹出进度提示，2 秒后把状态从故障置为空闲并记录一条运维日志；若电桩处于使用中，先提示"该电桩正在充电，重启会中断用户充电"并要求二次确认。
   - **标记故障 / 恢复正常**：手动切换状态。
4. 支持新增电桩（选择所属电站、填编号、类型、功率）与删除电桩（使用中的电桩禁止删除）。

**验收标准**：远程重启后状态变化并可在用户端看到该桩重新变为空闲。

---

### UC-A-06 充电站管理

**主流程**

1. 列表展示：电站 ID、站名、详细地址、经度、纬度、单价、总电桩数、在线率（非故障桩占比）。
2. 点击电站行，下方联动显示该站所有电桩的实时状态明细。
3. **新增电站**：对话框填写站名、地址、经纬度、单价、初始电桩数量与默认功率，提交后自动批量创建对应数量的电桩（编号规则 `站点缩写-序号`，如 `GG-01`）。
4. **修改电站**：可改站名、地址、经纬度、单价。
5. **删除电站**：遵循 BR-10，有电桩时禁止删除。

**异常流**：经纬度超出合法范围（经度 -180~180，纬度 -90~90）时校验失败并提示。

---

### UC-A-07 用户管理

**主流程**

1. 列表展示：用户 ID、手机号、昵称、钱包余额、注册时间、状态（正常/冻结）。
2. 顶部搜索框按手机号**模糊搜索**（`LIKE %关键字%`）。
3. 选中用户后可"冻结 / 解冻"，操作需二次确认。
4. 双击用户行查看该用户的订单历史。

**异常流**：冻结存在充电中订单的用户时提示"该用户有正在进行的充电，冻结后仍会保留订单"，允许继续。

---

### UC-A-08 智能预测展示

**主流程**

1. 页面读取 `load_prediction` 表，展示各电站未来 1 小时 / 6 小时 / 24 小时的预测充电量与预测空闲桩数。
2. 折线图对比"历史实际负荷"与"模型预测负荷"。
3. 提供"运行预测"按钮，调用 Python 脚本（`QProcess`）重新训练并刷新结果；脚本不可用时提示并保留上次结果。
4. 高峰时段以红色高亮标注，作为负荷预警。

## 5. 数据库端需求（UC-D）

### UC-D-01 数据表要求

必须包含以下表：`user`、`admin`、`station`、`charger`、`charging_order`、`ops_log`（运维日志）、`load_prediction`（预测结果）、`recharge_log`（充值流水，可选）。字段定义见《系统设计说明书》第 5 章。

### UC-D-02 初始化与种子数据

- 程序首次启动时若数据库文件不存在，自动执行建表脚本。
- 自动写入种子数据：1 个管理员（`admin/123456`）、至少 5 个电站（分布在不同经纬度）、每站 6-12 个电桩（快慢充混合，含 1-2 个故障桩）、约 30 天的历史订单（用于营收图表和 ML 训练有数据可看）。
- 已存在数据库时不重复初始化，通过 `schema_version` 表管理版本。

### UC-D-03 数据一致性

- 所有跨表写操作（预约、结算、批量建桩）必须在事务中执行。
- 外键约束开启（`PRAGMA foreign_keys = ON`）。
- 开启 WAL 模式（`PRAGMA journal_mode = WAL`）以支持两个客户端同时读写。

## 6. Web 可视化大屏需求（UC-W）

### UC-W-01 大屏布局

单页深色主题看板，1920×1080 基准，自适应缩放。分区：

- 顶部标题栏：平台名称 + 实时时钟。
- 左列：电桩状态占比饼图、电站充电量排行横向柱状图。
- 中列：四个核心指标卡（总充电次数、总营收、在线电桩数、注册用户数）+ 近 30 日营收趋势曲线。
- 右列：充电时段热力分布、快充/慢充占比环形图、未来 24 小时负荷预测曲线。

### UC-W-02 数据来源

管理端或 Python 脚本把 SQLite 聚合结果导出为 `web/public/data/dashboard.json`，前端定时（默认 30 秒）拉取刷新。这样大屏与 Qt 端解耦，也避免前端直连数据库。

### UC-W-03 交互

图表支持鼠标悬浮提示、图例切换；提供"数据截止时间"标注。

## 7. 机器学习子系统需求（UC-M）

### UC-M-01 数据准备

从 `charging_order` 导出训练集，按 `(电站, 日期, 小时)` 聚合，特征包括：小时、星期、是否周末、是否节假日、近 1/24/168 小时滞后负荷、滑动均值、电站编码、模拟天气（温度、是否降水）。标签为该小时充电量（度）。

### UC-M-02 模型

- 第一版：`RandomForestRegressor`（scikit-learn），可解释、训练快、无需 GPU。
- 评估指标：MAE、RMSE、MAPE，并与"用上周同一时刻值作为预测"的朴素基线对比，必须优于基线。
- 升级路线（可选）：LSTM / LightGBM，接口保持一致。

### UC-M-03 输出与回写

预测结果写入 `load_prediction` 表：电站 ID、预测生成时间、目标时间、预测充电量、预测空闲桩数、是否高峰。管理端与大屏读取该表展示。

### UC-M-04 可复现性

固定随机种子；脚本支持 `--train`、`--predict`、`--evaluate` 三种模式；训练产物保存为 `ml/models/load_rf.pkl`。
