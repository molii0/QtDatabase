## 2. 状态机（关键设计）

所有改状态的业务操作，执行前先查状态机(ChargeState.h)，非法转换直接拒绝并给原因。

**充电桩 `charger.status`**：0=空闲 → 1=已连接 → 2=充电中；3=故障。

| 转换 | 触发 | 谁做 |
| --- | --- | --- |
| 空闲 → 已连接 | 用户选桩下单 | orderConnect |
| 已连接 → 充电中 | 用户点“开始充电” | orderStart |
| 充电中 → 空闲 | 结算完成 | orderFinish |
| 已连接 → 空闲 | 取消订单/放弃 | orderCancel / 超时 |
| 空闲 ↔ 故障 | 管理员标记/恢复重启 | adminMarkFault / adminRecover |

**订单 `charging_order.status`**：0=待支付 → 1=充电中 → 2=已完成；3=已取消(从待支付)。
非法请求示例：待支付订单直接结算、充电中订单直接取消，都会被拒绝(HTTP 409)。

## 3. 数据表（核心 5 张 + 3 张扩展表 + 3 张设备接入表）

| 表 | 主要字段 |
| --- | --- |
| `user` | user_id、phone(唯一)、nickname、avatar、balance、debt(未结清欠费)、status(1正常/0冻结)、register_time |
| `admin` | admin_id、account(唯一)、password、created_at |
| `station` | station_id、name、code_prefix(缩写)、address、longitude、latitude、price |
| `charger` | charger_id、station_id(外键)、code、type(0慢/1快)、power、status(见状态机) |
| `charging_order` | order_id、order_no(唯一)、user_id、station_id、charger_id、status(见状态机)、energy、amount、**paid(实扣)、debt(欠费)**、start_time、end_time、created_at |
| `ops_log` | log_id、admin_account、charger_id/code、action、detail、created_at(运维日志) |
| `recharge_log` | recharge_id、user_id、amount、created_at(充值流水) |
| `load_prediction` | prediction_id、station_id、generated_at、target_time、load_kwh、idle_count、is_peak(预测) |
| `charger_telemetry` | telemetry_id、charger_id(外键)、ts、status(设备侧状态)、power、soc、energy、temperature(**设备遥测, 每秒一帧, 按桩裁剪保留最近 1000 帧**) |
| `charger_heartbeat` | charger_id(主键)、last_seen、status、uptime_s(**设备心跳, 每桩一行 upsert; now - last_seen 超阈值(建议 15s)即判定离线**) |
| `device_command` | command_id、charger_id(外键)、command、arg、status(0待执行/1已执行/2失败)、result、created_at、done_at(**Server→Device 命令通道**) |
| `schema_version` | version、applied_at(结构版本记录，见下) |

## 4. 版本迁移（数据库维护机制）

- 每次启动：建表(IF NOT EXISTS) → 按 `schema_version` 顺序补迁移 → 建索引(IF NOT EXISTS) → 需要时写种子；
- 建表/索引/迁移的 SQL 都在 **`db/` 目录的 .sql 文件**里，通过 `db.qrc` 打进程序资源，运行时从 `:/db/...` 读取执行(部署不依赖外部文件)；
- 迁移每步一个事务、只增不改不删表，已有数据不丢；当前迁移：
  1) `001_station_code_prefix.sql` station 补 `code_prefix` 并回填；
  2) `002_charger_status_remap.sql` 电桩状态码升级(旧 使用中1→充电中2、故障2→故障3)；
  3) `003_clean_duplicate_orders.sql` 加 BR-02/03 唯一索引前，先清理历史“同一用户/同一电桩多条活动订单”(保留最新并释放闲置电桩)；
  4) `004_add_user_avatar.sql` user 补 `avatar` 字段；
  5) `005_add_order_paid_debt.sql` charging_order 补 `paid/debt`(BR-06 欠费结算)；
  6) `006_add_user_debt.sql` user 补 `debt` 并回填历史订单欠费(欠费禁充)；
  7) `007_device_access.sql` 新建设备接入表 charger_telemetry / charger_heartbeat / device_command(当前结构版本 v7)；
- 新表(ops_log/recharge_log/load_prediction)与唯一索引都是 IF NOT EXISTS 幂等操作，新旧库启动都会补齐；
- 以后改结构：在 `db/migrations/` 新建 `00N_xxx.sql`、在 `applyMigrations()` 末尾加一步、把 `kSchemaVersion` +1 即可。

## 5. 并发 / 多线程

- 每线程独立连接(`db()`)，连接带线程 ID，线程结束自动清理；
- WAL + busy_timeout(5s) + 外键约束：用户端与管理端两个进程可同时读写同一 `charge_platform.db`；
- 状态转换全部在事务内完成，并用“带原状态守卫的 UPDATE”防并发抢桩/重复结算；
- BR-02/BR-03 另有**数据库级部分唯一索引**兜底：
  - `uq_order_user_active`：同一用户最多 1 条未结算订单(待支付/充电中)；
  - `uq_order_charger_active`：同一电桩最多被 1 条未结算订单占用。

## 8. 演示数据（种子，30 天）

admin/123456；5 个用户(1 冻结)；5 座电站(沈阳4+大连1，带缩写)；每站 6 台桩(缩写-01~06，
快慢混合、含 1 台故障)；近 30 天按真实分布生成的历史订单：周末单量更高、早/晚高峰时段集中、
充电时长按功率区分，约 600+ 条(固定随机种子，可复现)；1 条“充电中”订单(供演示结算)；
**未来 48 小时负荷预测**(每站每小时一行，约 240 行，供管理端“智能预测”页开箱即有曲线)。
规模刻意保持"正常量"——需要更多/更大历史数据时由 Web 用生成器自行补充，见 §8 后注。

> 电价采用**分时电价(峰谷平)**：station.price = 平段价(元/度，已下调到 0.65~0.92)，
> 另带 price_peak / price_valley(峰段 = 平×1.35、谷段 = 平×0.55)。时段划分：峰 08-12、17-21；
> 谷 23-07；其余为平。**订单金额按充电发生的分钟切段、用时段加权均价计算**
> (DBManager_price.cpp)，深夜充电明显比高峰便宜。

> **数据库文件怎么选**（`DBManager::resolveDefaultDbPath()`，兼容旧用法）：
> ① `--db <文件>` 显式指定（最稳，多进程共用时建议都写上）；② 当前目录已有
> `charge_platform.db` → 用它；③ exe 目录已有 → 用它；④ 都没有 → 用**工程根目录**
> `charge_platform.db`（`.pro` 的 `DEFAULT_DB_DIR`，不存在会自动建库并写种子）。
> 平台与模拟器都不传 `--db` 时会落到同一个库；排查“到底连的哪个库”用
> `QtDatabase.exe --print-db`（只打印路径，不建库不启动服务）。
> 参数解析是**宽松**的：不认识的参数只警告，不会让服务启动失败。
>
> Web 想要更多历史数据时不需要改代码：跑 `QtDatabase.exe --gen-history 180`（或调
> `POST /api/admin/demo/history`，见《03-REST接口文档》§29）即可把历史往前补，并顺手
> 补齐充值流水/运维日志/负荷预测——造数是"工具"，业务增删改仍只走 REST 接口。

## 11. 设备接入层（v7：Charger Device Simulator 对接）

**架构约定**：模拟充电桩(设备层)只与数据库层对接，数据全部入库；
接口层/界面层等其他层不与设备直连，一律经由数据库层读取——将来把 Simulator
换成真实 Embedded Linux 终端时，只需保持这套表结构/接口不变。

```text
Charger Simulator(设备层)                数据库层(DBManager)            其他层(接口/界面)
  遥测(1s)  ──────────────────────────>  charger_telemetry  <──────────  读取展示
  心跳(5s)  ──────────────────────────>  charger_heartbeat  <──────────  离线判定(last_seen 超时)
  状态投影  ──────────────────────────>  charger.status     <──────────  电桩列表/统计
  故障上报  ──────────────────────────>  ops_log            <──────────  运维日志页
  命令轮询(1s) <───────────────────────  device_command     <──────────  pushDeviceCommand 下发
```

- **状态映射(设备 6 态 → charger.status 4 态)**：idle→0 空闲；reserved/finished→1 已连接；
  charging→2 充电中；fault→3 故障；offline **不投影**(设备失联停止上报，由心跳超时判定离线)。
- **订单优先**：`syncChargerDeviceStatus` 对"有进行中订单(0/1)的电桩"跳过写入，
  这些桩的状态归订单流程(orderConnect/orderStart/orderFinish)负责，两条链路互不打架。
- **命令通道**：其他层调 `pushDeviceCommand(桩, 命令, 参数)` 下发
  (plug/start/stop/unplug/fault/recover/offline/online/restart)；
  设备每秒 `takePendingDeviceCommands` 领取执行，`finishDeviceCommand` 回填结果。
  掉线设备收不到命令，命令保持待执行、重新上线后补执行。
- **模拟器本体**在 `ChargerDeviceSimulator/`(独立 .pro，直接编译数据库层源码)，
  详见其 README.md；数据库文件与平台共用同一个 `charge_platform.db`(WAL 多进程并发)。
- 平台侧(REST/Qt 界面)展示遥测曲线、在线状态、下发命令的对接只需读写上述表/方法，按需接入。
