# 四、三天时间，我建议你只做 4 个东西

不要贪多。

## ① Charger State Machine

这是最值得做的。

定义：

```text
OFFLINE
   ↓
IDLE
   ↓
RESERVED
   ↓
CHARGING
   ↓
FINISHED
   ↓
IDLE
```

以及：

```text
任何状态
   ↓
FAULT
```

然后：

```text
FAULT
 ↓
RECOVER
 ↓
IDLE
```

这样你就不再是简单地：

```cpp
if (charging)
    soc += 1;
```

而是开始真正模拟一个**设备状态机**。

---

# 五、② 模拟设备自身运行，而不是让 Qt 替它运行

这是我认为最重要的一点。

你们原来的设计可能是：

```text
Qt Timer
   ↓
修改数据库
   ↓
SoC变化
```

这其实还是：

> 软件在假装充电。

你现在应该把它抽象成：

```text
Charger Simulator
       │
       │ 每秒/每几秒
       ↓
模拟设备状态
       │
       ↓
产生 Device Telemetry
       │
       ↓
Server
       │
       ↓
Database
```

例如：

```json
{
    "charger_id": 1,
    "status": "charging",
    "power": 60.0,
    "soc": 62.5,
    "energy": 23.7,
    "temperature": 32.1
}
```

这个 JSON 就相当于真实设备上传的 telemetry。

---

# 六、③ 做一个 Heartbeat

这个非常容易做，但**非常有“真实生产环境”的感觉**。

设备每 5 秒：

```text
POST /api/device/heartbeat
```

服务器记录：

```text
charger_id
last_seen
```

然后：

```text
if now - last_seen > 15s:
    OFFLINE
```

你甚至可以在演示的时候：

> 点一下“模拟设备掉线”

然后：

```text
Charger #001
       ↓
停止 heartbeat
       ↓
15 sec
       ↓
Server detects timeout
       ↓
设备状态 → OFFLINE
       ↓
管理员界面出现故障
```

这比“LED 闪一下”有价值很多。

因为你实际上实现了一个最基本的：

> **device health monitoring**

---

# 七、④ 做一个 Device Command

反方向也要有通信。

服务器：

```text
POST /device/1/restart
```

模拟设备：

```text
收到 restart
       ↓
执行
       ↓
返回 ACK
```

于是你有了：

```text
                    Server
                       │
          ┌────────────┴────────────┐
          │                         │
       Telemetry                 Command
          │                         │
          ↓                         ↓
       Device ←──────────────── Device
```

也就是：

> **Device → Server**

和：

> **Server → Device**

双向通信。

这就已经是一个非常标准的 IoT Device Management 雏形。

## 所以我现在给你的结论会比较明确

**这三天不要买板子，也不要试图硬做真实嵌入式。**

你现在应该做的是：

> **把软件中的“虚拟充电桩”提升为一个具有独立设备边界的 Charger Simulator。**

最低实现：

```text
1. Device State Machine
2. Telemetry
3. Heartbeat
4. Server → Device Command
5. Device → Server Communication
6. Offline / Fault Simulation
```

如果还有时间，再做：

```text
7. 日志
8. 多设备模拟
9. 网络断开 / 自动重连
10. 简单的设备管理界面
```

其中 **多设备模拟**我尤其推荐。你可以一次启动：

```text
Charger #001
Charger #002
Charger #003
...
Charger #010
```

让它们各自产生 telemetry、heartbeat 和随机故障。

这样老师演示时看到的就不是：

> “我们模拟了一个充电桩。”

而是：

> **“这是一个充电站设备管理系统，我们用多个独立的 Charger Device Simulator 模拟真实充电桩，每个设备独立产生遥测数据、发送心跳，并接受服务端下发的控制命令；未来可以将 Simulator 替换成运行 Embedded Linux 的真实终端。”**

这个完成度，对于**只剩三天的项目实训**来说已经足够合理，而且最重要的是：**它不是一次性的课程作业，而是在给你以后真正学习 Embedded Linux 留接口。**
